# LP 매트릭스 사용 안내서

`/lp-matrix` 탭의 **사용자 설명서**. 설계 근거·구현 기록은 [`lp-system-design.md`](../lp-system-design.md) §13이 정본이고, 이 문서는 "화면을 어떻게 읽고 어떻게 쓰는가"를 다룬다.

> 대상 버전: v2 Phase 1~5 (2026-07-08 완결). 화면과 이 문서가 어긋나면 코드/설계 문서가 정본.

---

## 1. 이 화면은 무엇인가

ETF LP 운영의 **하루 사이클 전체**를 한 화면에 올린 워크플로 대시보드다.

```
호가 결정 → 체결 기장 → 선물 헤지 → 보유(손익·리스크 관찰) → 정리(출구 선택)
   ▲                                                              │
   └──────────────── 재고 skew가 다시 호가에 반영 ◄────────────────┘
```

운영 모델의 전제 (현 OMS 제약 반영):

- ETF 체결 시 넷팅 바스켓 헤지는 불가 → **체결 직후 헤지는 지수선물**(K200F·미니·KQ150F)로만.
- 넷팅은 바스켓 레이어가 아니라 **선물 레이어**에서 얻는다 — 북 전체 순 델타 기준으로 선물 계약수만 맞추면 반대 방향 재고가 자동 상쇄.
- 그 결과 북은 항상 `ETF 재고 − 지수선물 오버레이 = 베이시스 포지션 + 잔차` 구조가 되고, 정리는 **기회가 왔을 때** 넷팅 바스켓·호가 건조·설정환매 중 가장 싼 출구로.

## 2. 화면 구성

화면은 **4대 숫자(공통 고정)** 아래에 서브탭 2개로 나뉜다 — 운영 동선(체결 전 → 체결 후)에 맞춘 구성. 탭은 `?view=pre|post`로 URL에 반영되어 새로고침에도 유지되고, 전환해도 실시간 구독·입력 상태는 그대로 살아있다.

- **[체결 전 — 호가·기회]**: 호가 제안 보드(§2.3) + 지수 베이시스 z 요약 스트립 + 파라미터 패널. "지금 어디에 얼마로 호가를 댈까"를 보는 뷰.
- **[체결 후 — 북 관리]**: 헤지 정합 보드(§2.5) → 헤지 티켓·라우터(§2.4) → 북 원장(§2.6) → 베이시스 북(§2.2) → P&L(§2.7) → 출구(§2.8). "체결된 북을 어떻게 관리·정리할까"를 보는 뷰.

아래 소절 번호는 패널 기준이며, 실제 화면에서는 위 두 탭에 나뉘어 배치된다.

### 2.1 4대 숫자 (최상단 카드 4개)

| # | 카드 | 의미 |
|---|---|---|
| #1 | 시장 노출 | 북 전체를 KOSPI200(K2G01P) 단일 팩터로 환산한 노출 |
| #2 | 베타조정 델타 | 북이 지금 얼마나 열려 있나 (gross 병기) |
| #3 | 잔차위험 1σ | 팩터 헤지 후 남는 종목 고유 위험 — 시장을 완벽히 헤지해도 하루에 이만큼은 움직일 수 있다 |
| #4 | 당일 P&L | 총액 + 미니 분해 한 줄. 상세는 P&L 패널(§2.7) |

### 2.2 베이시스 북 (4층 분해 + 페어 테이블)

북 전체를 **완전 분해**한 요약 스트립:

```
① 방향 델타  |  ② 지수 베이시스 (가족별 notional, 10bp당 손익)  |  ③ 종목 베이시스  |  ④ 잔차
```

- **① 방향**: 헤지하고 남은 순 방향 노출. 헤지 티켓이 0이면 여기가 ≈0.
- **② 지수 베이시스**: ETF 재고와 지수선물 오버레이가 반대 부호로 매칭된 만큼 = "사실상 지수 베이시스를 N억 들고 있다". 옆의 z-score는 **excess 기준** (실측 베이시스 − 이론 베이시스, 만기 정규화 완료 — 월물 롤 영향 없음)의 60일 분포 대비 위치. |z|≥2면 warning색 — 정리 타이밍 후보.
- **③ 종목 베이시스**: 현물↔주식선물 페어의 합. 아래 페어 테이블에 상세 — 진입→현재 베이시스, 초과(이론 대비), **수렴손익**, 만기 D-day, 연환산.
- **④ 잔차**: #3와 동일 소스.

페어 테이블 읽는 법:
- 수렴손익 = `(진입 베이시스 − 현재 베이시스) × 매칭 주수` — 페어 MTM 그 자체. 현물롱+선물숏이면 베이시스가 줄수록 이익.
- **만기 D-5 이내면 warning** — 주식선물은 현금결제라 만기 수렴은 보장되지만, 만기일에 현물 leg를 어떻게 할지(매도 or 롤) 액션이 반드시 필요하다.
- 같은 종목 여러 월물 보유 시 현물은 **근월부터 순차 배분**되어 페어링된다.

### 2.3 호가 제안 보드 (메인)

유니버스 12종 × 행. 컬럼:

| 컬럼 | 의미 |
|---|---|
| 현재가 / FV_futures | 시장가 vs **지수선물 기준 자체 기준가** (산식 §4.1). 옆의 `mid`/`last` 배지 = 갭 계산에 쓴 기준가 소스 |
| 차익·진입선 | 갭이 매수차/매도차 중 어느 쪽이고 요구엣지(진입선) 대비 몇 %까지 왔는지. "매수차 +6.2bp / 진입선 8.0bp (78%)" — 도달률 100% 넘으면 진입선 도달로 행 강조 |
| 제안 매수/매도 | 예약가격(FV+skew) 중심 ±요구엣지, 호가단위 스냅 완료된 실주문 가능 가격. 옆 작은 숫자 = 엣지 bp |
| 제안 수량 | 재고 한도 잔여 기준 |
| skew bp | 재고가 밀어낸 호가 중심 이동. 롱 재고 → 음수 → 양쪽 호가가 아래로 = 시장이 내 재고를 사가게 유도 |
| 신선도 | 입력 데이터 나이. 오래되면 그 행 판단 보류 |
| 모드 | `K200 ×2`(지수형×배수) / `β1.07`(섹터형) |

- **MID 기반 갭**: 호가 스프레드가 넓은 ETF는 체결가(last)가 아니라 **호가 중간값(mid = (최우선매수+최우선매도)/2)**으로 갭·제안 호가를 계산한다 (더 정확). 호가가 6초 이상 stale이거나 없으면 last로 자동 폴백하고 배지가 `last`로 바뀐다. 실시간 ETF 호가는 키B WS로 받으므로 **09:00~15:45에만 mid**, 그 외 시간대·mock은 last.
- **매수차/매도차**는 이 화면을 지수 차익거래 관점으로 읽는 방식이다: ETF가 FV 대비 싸면(갭 음수) "ETF 매수 + 선물 매도"의 매수차, 비싸면 매도차. 도달률은 지금 갭이 진입할 만한 수준(요구엣지)에 얼마나 근접했나를 보여준다.

- **행 클릭 → 확장**: 요구엣지 분해(기본/버퍼/잔차/skew/헤지비용) + FV 입력값(r_implied·함축 현물지수·선물코드·LS 이론가) + 수량 근거.
- **dim 처리된 행**: 호가 금지 상태 — 사유가 행에 인라인 표시 (지수선물 미수신, prev 결측, r_implied 극단(서킷 의심) 등). 사유가 해소되면 자동 복귀.
- 행 순서는 고정 (갭 크기로 재정렬하지 않음 — 색상으로만 강조).

### 2.4 헤지 티켓 + 베이시스 라우터 (한 행 2분할)

**헤지 티켓** — "지금 북 순 델타를 0으로 만들려면":
- 가족별(K200/KQ150) 카드: `KQ150F(A06...) 3계약 매도` / `K200F 2계약 매도 + 미니 1` / `헤지 불필요 (넷팅)`.
- 원장의 기존 지수선물 포지션은 이미 차감돼 있다 — 티켓은 항상 **추가로 필요한** 계약만.
- 라운딩 잔차(계약 단위로 못 맞추는 꼬리)가 원화로 표시. K200은 미니(1/5)로 잔차를 줄인다.
- "기장" 버튼 → 원장 입력 폼에 코드·방향·수량 프리필. **집행은 수동** — LENS는 제안만 한다.
- usable=false + 사유가 뜨면 (기존 선물 시세 stale 등) 그 가족 티켓은 신뢰하지 말 것 — 조용히 틀린 티켓을 내느니 명시적으로 죽이는 설계다.

**베이시스 라우터** — "이 주문, 현물로 할까 선물로 할까":
- 코드(자유 형식)·방향·수량 입력 → 판정 카드: 실시간 베이시스 vs **자체 이론 베이시스**(금리×잔존일), 초과분이 임계(기본 5bp) 넘으면 선물 대체 제안.
  - 매도 leg: 베이시스 rich(+) → 선물 매도 대체 (비싸게 팔리는 선물을 판다)
  - 매수 leg: 베이시스 cheap(−) → 선물 매수 대체
- "선물 대체로 기장" 버튼 → 원장에 진입 베이시스가 같이 기록되고, 이후 베이시스 북 페어 테이블에서 수렴이 추적된다. 이때 원장 기록은 **주수 단위**(계약수×10 환산분) — 계약 라운딩으로 주문 수량과 몇 주 차이날 수 있다(잔차 표시 확인).

### 2.5 헤지 정합 보드 (원장 진단 — 무기억)

"지금 원장이 PDF 기준으로 알맞게 헤지돼 있는가"를 **현재 상태만으로** 매번 새로 판정한다 (과거 매매 기록·의도 태그에 의존하지 않음 — 엑셀 임포트로 원장이 매일 재구성돼도 항상 일관).

요약 스트립: `정합 142 · 대체 헤지 3 · 매크로 106 · 미설명 7종목 (δ K200 +2.1억)` — **미설명이 진짜 리스크**이자 리밸런싱 대상.

| 분류 | 의미 |
|---|---|
| 정합 | PDF 요구 헤지가 현물 숏만으로 맞음 |
| 대체 헤지 | 현물로는 부족하지만 그 종목 주식선물이 채움 (베이시스 대체 매매의 흔적) |
| 매크로 | 종목 gap이 남아 있으나 지수선물이 가족 net 델타를 커버 |
| 매크로(상쇄) | 델타는 커버됐지만 그 종목 |gapδ|가 임계 초과 — 종목 간 상쇄에 기대는 상태 (warning) |
| 미설명 | 어느 수단으로도 설명 안 됨 → 리밸런싱 주문 제안 |

- 커버리지는 **가족 net 델타 기준** — 종목 간 상쇄된 gross 리스크는 가족 테이블의 gross Σ|δ| 컬럼과 "상쇄 큼" 배지로 별도 감시 (잔차위험 #3과 연결).
- **선물 과다**: 지수선물이 필요량을 초과하면 종목 주문은 0이 되고 초과분이 "선물 초과 (→티켓)"로 표시 — 청산은 헤지 티켓 몫.
- **운영 규율 (중요)**: 리밸런싱 주문과 헤지 티켓은 같은 델타의 회계 분해라 **동시 실행 금지** — 리밸런싱 실행·기장 후 티켓이 자동 재계산되면 그때 티켓 확인.
- PDF 변경일: 미설명 종목이 확 늘어난 게 정상 — 주문표 복사로 리밸런싱 매매.
- 선물지수·레버리지 ETF는 PDF 환산 불가라 베타·배수 요구 델타로만 가족 풀에 들어감.

### 2.6 북 원장

**모든 계산의 뿌리.** 여기 기장된 것만 북이다.

- **이월(carryover)** vs **체결(fill)** 분리 — 기존 보유는 이월로, 당일 매매는 체결로 입력.
- 자산유형 4그룹: ETF 재고 / 지수선물 오버레이 / 주식선물 / 현물. 자동 분류 (코드로 판별, 수동 override 가능).
- **단위 규약 (중요)**: ETF·현물·주식선물 = **주수**, 지수선물 = **계약수** (행에 "N계약"/"N주" 표기). 평가노출은 지수선물의 경우 계약×포인트×승수로 환산돼 있다.
- **체결은 체결 직후 바로 기장할 것** — 유니버스 ETF면 기장 순간의 FV가 자동 첨부되어(P&L 스프레드 귀속·markout의 기준) 나중에 몰아서 넣으면 그 정보가 소실된다(스프레드 미귀속으로 분류).
- 베이시스 페어가 성립하면 행에 "베이시스" 태그.

**회사 원장 엑셀 업로드** (수동 기장 대신 일괄 반영):

- "엑셀 업로드" 버튼 → 원장 화면 파일들(.xls/.xlsx) 다중 선택. **3454(LP·차입 장부)와 2514(선물)가 포지션 소스**고, 5264는 같이 올리면 담보가능수량 마이너스 경고만 추출 (5264만으로는 반영 불가).
- 화면 유형·LP/차입 구분은 자동 판별 (계정코드 031/052). 차입펀드의 매수↔매도 컬럼 반전, 가입고(가상 수량) 제외, LP−차입 종목 넷팅 전부 자동.
- 3454의 **전일 장부 → 이월, 당일 매수/매도 → 체결**로 분리 기장. `전일±당일=당일장부` 정합이 깨진 종목은 경고로 표시 (반영은 당일 장부 기준).
- **미리보기를 반드시 확인**하고 반영할 것: 인식 요약(파일별 화면·펀드 유형), 반영될 포지션, 선물 환산 명세("3,000계약 → 30,000주 ×10" — 단위가 다르면 계약수/주수 토글), 경고, **전체 교체 시 삭제될 기존 종목** 목록.
- 기본은 **전체 교체** — 엑셀 스냅샷이 정본이 되고 기존 원장은 재구성됨 (청산 종목 유령 방지). 안전장치: 포지션 0건이거나 파싱 실패 파일이 섞여 있으면 서버가 확정을 거부, 중복 첨부 파일은 자동 무시.
- 엑셀로 반영된 당일 체결은 FV 스냅샷이 없어 스프레드 미귀속으로 분류된다 — 스프레드 귀속이 필요한 체결은 장중 직접 기장이 정확.

### 2.7 P&L 분해 + MARKOUT + 한도 게이지

**당일 P&L 5분해** (전일 종가 기준 세션, 실현손익 포함):

| 항목 | 정의 | 읽는 법 |
|---|---|---|
| 스프레드 | Σ(체결 시점 FV − 체결가)×방향 | 호가가 좋았나. 지속 음수면 호가 설정 재검토 |
| 베이시스(종목) | 페어 수렴손익 합 | 이 전략의 본체 (지수 베이시스 당일 변화는 v1 미산출 — 표시로 명시) |
| 잔차·방향 | 총액 − 나머지 (잔여 역산) | 감내 중인 위험의 실제 비용/수익 |
| 캐리 | 현물성 노출만: 롱 −, 숏 + (선물 제외) | 보유 일수의 기울기 |
| 헤지 비용 | 당일 선물 체결 명목 × 수수료율 | 넷팅이 아껴주는 돈의 반대편 |

- **MARKOUT (역선택)**: 체결 5분/30분 후 가격이 체결 방향 대비 어떻게 움직였나. **음수 평균이 계속되면 정보 열위 카운터파티에게 채워지고 있다는 통계적 증거** → 스프레드 확대·수량 축소 신호. 마크는 5초 주기 관측이라 시점 오차 ±수초(정상)이며, 가격이 60초 이상 stale이면 기록하지 않는다.
- **스프레드 미귀속**: FV 스냅샷 없이 기장된 체결(비유니버스 종목, 체결 한참 뒤 몰아 기장)은 스프레드를 계산할 수 없어 미귀속으로 분리되고 잔차 항에 흡수된다 — 미귀속 건수가 많으면 "체결 즉시 기장" 습관부터.
- **한도 게이지 4개**: 순 베타델타 / 잔차 총량 / ETF별 재고 / 베이시스 VaR. 80% 초과 주황, 100% 초과 빨강. 한도값은 파라미터 패널에서.
- 하단 caveats 줄은 장식이 아니다 — "이 숫자를 지금 얼마나 믿어도 되는가"의 목록 (장중 재시작 왜곡, 비유니버스 폴백 등).

### 2.8 넷팅 바스켓 빌더 + 출구 3개 비교

**넷팅 바스켓 빌더** — 메인 출구:
- "생성" 버튼 → 보유 ETF 전체의 PDF를 합산해 **종목별 순 주수 주문표** 스냅샷. 롱 ETF는 매도 leg, 숏 ETF는 매수 leg로 자동 상쇄 — 예: KODEX 200 롱 + TIGER 200 숏이면 겹치는 종목이 소거되어 잔여만 남는다 (실측: 1CU씩 반대 보유 시 gross 65억 → 순 785만, 0.1%).
- leg별: 예상대금 / **ADV%**(20일 평균 거래량 대비 — 높으면 임팩트 주의, 캡 초과 warning) / 거래세(매도 20bp) / 주식선물 배지(클릭 → 라우터 프리필 — 베이시스 유리하면 그 leg만 선물 대체).
- 선물 오버레이 청산 안내: 바스켓 집행과 **동시에** 반대 방향으로 청산할 계약수 (델타 중립 유지).
- "주문표 복사" → 탭 구분 텍스트 (엑셀/주문 시스템 붙여넣기).
- **제외 종목**: 선물지수 추종(114800·252670·251340)과 레버리지(122630·233740)는 PDF가 선물/스왑 혼합이라 현물 바스켓 환산 불가(레버리지는 현물 leg만으론 실델타 ~50%) — 제외 목록에 사유와 함께 표시. 이들은 직접 매매나 설정환매로.
- 하단 "현금 leg (음수=수취)": PDF 현금분의 주문 규약 표기 — 롱 ETF 정리 시 음수(현금을 받는 쪽)가 정상.

**출구 3개 비교** — 동일 기준(재고 명목 대비 순 bp) 정렬:
1. **넷팅 바스켓 + 선물 청산**: 지금 즉시 정리 시 순액
2. **호가 자연 건조**: skew로 스프레드 받으며 며칠에 걸쳐 정리 (예상 소요일 입력) — 스프레드 수취 − 캐리
3. **설정/환매**: CU 도달분만, AP 수수료 차감
"최선" 뱃지가 현재 가장 유리한 출구. 각 카드의 각주(근사 가정)를 반드시 같이 볼 것.

## 3. 하루 운영 워크플로 (권장)

1. **장 시작 전**: 원장 확인 — 이월 포지션이 실계좌와 맞는지. 만기 D-day warning 여부. 한도 게이지 여유 확인.
2. **호가**: 호가 보드에서 갭·엣지 확인 → 제안 bid/ask 참고해 OMS에 호가. dim 행은 건드리지 않는다.
3. **체결되면 즉시**: ① 원장에 체결 기장 (FV 자동 첨부) → ② 헤지 티켓이 갱신됨 → 티켓대로 선물 집행 → ③ 선물 체결도 기장. 개별 종목 leg가 있으면 라우터로 현물/선물 판정 후 기장.
4. **보유 중**: 4대 숫자 + 베이시스 북으로 상태 관찰. P&L 분해로 "뭘로 벌고 있나" 확인. markout 평균이 음수로 기울면 스프레드/수량 조정.
5. **정리 신호**: 지수 베이시스 z-score 하이라이트, 또는 출구 비교에서 넷팅 바스켓이 양수로 올라올 때 → 바스켓 생성 → leg별 선물 대체 검토 → 주문표 복사 → 집행 → **집행분도 원장에 기장** (P&L 실현 반영).
6. **만기 주간**: 페어 테이블 D-5 warning 뜨면 현물 leg 처리 계획 (만기 수렴은 보장, 액션은 필수).

## 4. 산식 레퍼런스

### 4.1 FV_futures (호가 앵커)

```
S_impl  = F / (1 + r × d/365)          F=지수선물가, r=회사금리, d=잔존일 (배당 무시 — v1)
r_impl  = (S_impl − S_전일종가) / S_전일종가
지수형:  FV = 전일 adj_close × (1 + L × r_impl)     L = 추적배수 (+1/+2/−1/−2)
섹터형:  FV = 전일 adj_close × (1 + β × r_impl)     β = 60일 OLS (vs KOSPI200)
```

### 4.2 호가 제안

```
skew    = −γ × (재고 노출 억원) × (σ일 %)² × hold_days     [bp]
half    = max(0, base_spread + adverse_buffer + residual_charge)  [bp]
예약가격 = FV × (1 + skew/10⁴)
제안 bid = 예약가격 × (1 − half/10⁴) → 호가단위 내림
제안 ask = 예약가격 × (1 + half/10⁴) → 호가단위 올림
```
skew는 스프레드를 벌리는 게 아니라 **중심을 옮긴다** (Avellaneda-Stoikov 간소화). 호가단위: 2,000원 미만 1원 / 이상 5원 (경계 교차 시 재스냅).

### 4.3 헤지 티켓

```
가족별 잔여델타 = Σ(지수형 ETF 노출×L) + Σ(섹터형·현물 노출×β) + 기존 지수선물 델타
계약 델타 = 선물가 × 승수      (K200F 250,000 / 미니 50,000 / KQ150F 10,000 원/pt)
티켓 = 잔여델타 반대 방향으로 본계약 절사 + (K200만) 잔차를 미니로 반올림
```

### 4.4 종목 베이시스

```
이론 베이시스 = 현물가 × r × d/365            (배당 무시 — v1)
초과분(excess) = 실시간 베이시스 − 이론
수렴손익      = (진입 베이시스 − 현재 베이시스) × 매칭 주수 (부호: 현물 방향)
지수 z-score  = (현재 excess − 60일 excess 평균) / 60일 excess 표준편차
               (행별 만기 정규화 완료 — 월물 롤 영향 없음)
```

### 4.5 당일 P&L

```
총액 = Σ 포지션 × (현재가 − 기준가) × 승수  +  Σ 당일 체결 × −(체결가 − 기준가) × 승수
     (기준가 = 전일 종가, 결측 시 당일 첫 관측가 — 두 항이 같은 기준가라 왕복·신규진입에서 소거)
스프레드 = Σ (기장 시점 FV − 체결가) × 부호수량
markout  = (마크 시점 가격 − 체결가)/체결가 × 체결 방향 × 10⁴   [bp, 음수=역선택]
```
